# Аудит Lighthouse и оптимизация сайта

Отчёт о прогоне Lighthouse по всем маршрутам сайта и о правках, сделанных
по его результатам. Ветка `feauter/lighthouse-audit`.

## Как воспроизвести замер

Порт 3000 на машинах разработчиков обычно занят Docker-стеком или `next dev`,
а `pnpm start` в этом случае молча падает с `EADDRINUSE` — сервер остаётся
старым. Замер по dev-сборке недостоверен: там нет минификации и подключён
оверлей devtools. Поэтому поднимаем прод на свободном порту:

```bash
cd src
pnpm build
PORT=3100 pnpm start

# в другом окне, из корня репозитория
BASE_URL=http://localhost:3100 node scripts/lighthouse.mjs             # mobile
BASE_URL=http://localhost:3100 node scripts/lighthouse.mjs --desktop
```

Скрипт откажется работать, если на указанном адресе отвечает dev-сервер.

Флаги: `--desktop`, `--threshold=95`, `--runs=1` (черновой прогон),
`--only=/price,/vrachi`. Отчёты в формате JSON складываются
в `.lighthouse/<профиль>/` (каталог в `.gitignore`).

Список маршрутов лежит в `scripts/routes.mjs` и общий с `check-metadata.mjs`:
35 статических плюс по одному живому адресу блога и вакансий, которые
подтягиваются из `sitemap.xml` запущенного сервера. Страница 404 в список
не входит — Lighthouse не оценивает ответы с кодом, отличным от 200.

## Что мешало и что сделано

Разбор идёт в порядке вклада в оценку.

### 1. Весь сайт приходил из SSR невидимым

`shared/ui/animation-wrapper` — обёртка для появления секций при прокрутке.
Её хук выдавал `opacity: 0` во **встроенном стиле серверной разметки**, то есть
ни одна секция, включая первый экран, не была видна до того, как загрузится
и отработает JS, сработает `IntersectionObserver` и завершится переход 376 мс.

Это и держало LCP на 4–9 секундах при FCP 1.1 с: отрисовывать было нечего.

Теперь секция, уже попавшая в первый экран, показывается сразу и без анимации,
а появление при прокрутке осталось тому, что ниже сгиба. Элемент проверяется
по `getBoundingClientRect()` в эффекте, до того как пользователь до него
доскроллит.

**Это видимое изменение поведения:** первый экран больше не «въезжает» при
загрузке страницы. Если анимация на первом экране нужна, её можно вернуть
отдельным пропом, но она стоит примерно 2.5 секунды LCP.

Файл: `src/shared/ui/animation-wrapper/hooks/use-animated-entering.ts`.

### 2. Предзагрузка четырёх начертаний шрифта

`next/font/local` по умолчанию предзагружает все объявленные файлы. На каждой
странице это 126 КБ с высоким приоритетом, которые начинали качаться
одновременно с LCP-картинкой и отбирали у неё канал.

Поставлен `preload: false`. При уже настроенном `display: swap` текст рисуется
системным шрифтом сразу, начертания подтягиваются следом. Проверено: CLS
остался нулевым (0.0000–0.0004 при пороге 0.1). FCP при этом вырос
примерно на 0.5 с, но LCP упал сильнее, и с учётом весов Lighthouse
(LCP 25 %, FCP 10 %) итог выигрывает около 6 пунктов.

Файл: `src/shared/config/local-font.ts`.

### 3. Карта Яндекса грузилась на каждой странице

`<YandexMap>` рендерился безусловно в `widgets/layout`, поэтому
`api-maps.yandex.ru` подтягивался на всех маршрутах при монтировании — включая
прайс-лист и юридические страницы. Туда же уезжал Swiper (74 КБ), который
импортируется только в балуне карты и больше нигде на сайте.

Карта теперь монтируется по `use-intersection-observer` (хук уже был
в `shared/hooks`, но нигде не вызывался) с `rootMargin: 200px`; контейнер
и раньше имел фиксированную высоту, так что сдвига макета не возникает.
Балун вынесен в отдельный `dynamic`, и Swiper уходит из стартового чанка.

Заодно удалён мёртвый `shared/ui/yandex-map` — ноль импортёров, при этом
статический импорт `@pbe/react-yandex-maps`.

Файлы: `src/widgets/yandex-map/index.tsx`, `src/shared/ui/yandex-map/` (удалён).

### 4. Модальные окна висели смонтированными

`shared/ui/modal` использовал `<dialog open>` постоянно, скрывая окно через CSS.
Четыре глобальные модалки на каждой странице: их содержимое попадало в дерево
доступности, ловило Tab и тянуло свои картинки (только `alexik.png` — 105 КБ
на каждой странице).

Теперь содержимое монтируется, пока окно открыто, и снимается после перехода
(350 мс), а сам `<dialog>` получает `inert`, когда закрыт. Кнопке закрытия
добавлен `aria-label`, кнопка-подложка убрана из обхода (`tabIndex={-1}`,
`aria-hidden`), чтобы не экспонироваться как отдельный элемент управления.

Файл: `src/shared/ui/modal/index.tsx`.

### 5. Инлайн-CSS раздувал каждый документ

При `experimental.inlineCss: true` весь CSS страницы уезжает в HTML. На главной
это было 445 КБ в документе на 1.46 МБ.

Причина раздува нашлась в `@mixin responsive`: он печатал **четыре** блока
на каждый вызов, и четвёртый (`min-width: 1441px`) дословно повторял первый.
Блок удалён. Расхождение возникает ровно на ширине 1441 px, где теперь
применяется делитель 14.4 вместо 14.41 — разница 0.07 %.

Инлайн-CSS: 445 → 320 КБ, документ главной: 1.46 → 1.04 МБ.

Флаг `inlineCss` оставлен включённым: Lighthouse меряет холодный первый визит,
где отсутствие блокирующего запроса за стилями выигрывает.

Файл: `src/shared/styles/mixins/responsive.css`.

### 6. Куки-панель становилась LCP-элементом

Панель появлялась через 500 мс после гидрации и плавно проявлялась ещё 300 мс.
На всех страницах без крупного героя она оказывалась последним крупным
отрисованным блоком, то есть LCP-элементом.

Теперь она приходит в серверной разметке видимой и попадает в первую отрисовку.
Тем, кто уже согласился, её скрывает инлайн-скрипт в `app/layout.tsx`,
выполняющийся до первой отрисовки, — мигания не будет.

Файлы: `src/features/cookies-panel/`, `src/app/layout.tsx`.

### 7. Изображения

`src/public` весил 40 МБ. Написан `scripts/optimize-images.mjs` — обычный
node-скрипт поверх системных `cwebp`, `dwebp` и `sips`, без новых зависимостей
(`sharp` в проекте недоступен: в `pnpm-workspace.yaml` стоит
`allowBuilds: sharp: false`, нативный модуль не собран).

Скрипт работает в двух режимах: `RESIZE` — уменьшение исходников, которые
кратно больше места отрисовки; `RECODE` — пережатие на месте с сохранением
имени и формата, чтобы не трогать константы контента. Есть `--dry-run`.

| Что | Было | Стало |
|---|---|---|
| `mock/supervisory/*-icon.png` (4 файла 2000×2000, рисуются как иконки 150 px) | 7.5 МБ | 113 КБ (webp 320×320) |
| `system/output-onlinepngtools.png` (3185×2800) | 1.2 МБ | 279 КБ |
| Постеры героя главной | 59 КБ (2720 px на мобильном) | 3.9 КБ (мобильный вариант) |
| `mock/volkovo/volkovo-hero.webp` | 528 КБ | 231 КБ + мобильный 54 КБ |
| `mock/volkovo/zup.png` | 212 КБ | 38 КБ (webp уже лежал рядом неиспользованным) |
| `system/teeth-brath.webp` (LCP на `/volkova`) | 79 КБ | 29 КБ |
| `src/public` целиком | 40 МБ | 28 МБ (из них 9.5 МБ — PDF) |

Слайдам героя 1, 2, 4 и 6 добавлены мобильные варианты — раньше на телефон
отдавались десктопные файлы.

### 8. Слайдер героя тянул все шесть слайдов сразу

Слайды лежат друг на друге и все попадают во вьюпорт, поэтому `loading="lazy"`
их не сдерживал: на главной это было больше 600 КБ картинок при загрузке.
Теперь в разметке держатся только показанные слайды и следующий за текущим.

Файлы: `src/widgets/hero-slider-section/index.tsx`, `.../ui/hero-slide/index.tsx`.

### 9. Доступность и разметка

- Шесть `<h1>` на главной (по одному на слайд) сведены к одному; остальные
  слайды отдают заголовок абзацем с теми же стилями.
- `alt="Background image"` стоял по умолчанию у всех 65 картинок главной —
  английская подпись на русскоязычном сайте. Для оформительских изображений
  правильный `alt` пустой, он и поставлен по умолчанию.
- `aria-expanded` и `aria-haspopup` у переключателя филиалов, `inert`
  на закрытом списке; `aria-expanded` у кнопки меню.
- Восьми `<img>` с талисманом и иконкам надзорных органов проставлены
  `width`/`height`/`loading`/`decoding` — закрывает `unsized-images`
  и убирает сдвиг макета.
- `Picture` научился принимать `width`, `height` и `decoding`
  (по умолчанию `async`).

### 10. Мёртвый код

Удалены `@reduxjs/toolkit` и `redux` — ноль ссылок в исходниках, ни store,
ни slices, ни Provider. Удалён `shared/ui/yandex-map` (ноль импортёров).

## Ограничения локального замера

- **Бэкенд.** `API_URL` смотрит в `host.docker.internal:8000`. Когда контейнер
  не поднят, главная получает ошибку CORS на запрос блога, и Best Practices
  на ней падает со 100 до 96. На проде бэкенд доступен.
- **Ключ карты.** `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` локально не задан. После
  гейтинга карта не грузится, пока до неё не доскроллят, а Lighthouse не
  скроллит, — на оценку это больше не влияет, но и сама карта локально
  не проверена.
- **Заголовки кэширования.** Замер идёт напрямую по `next start`, без nginx,
  поэтому проблема с `Cache-Control` для файлов из `public/` (см. ниже)
  в локальных отчётах не видна.

## Что осталось сделать

1. **`docker/prod/nginx/nginx.conf`.** Локация `/static/` бесполезна — Next
   такого пути не отдаёт. Всё содержимое `public/` (картинки, шрифты, PDF)
   уходит без `Cache-Control`. Нужна локация по расширениям с `expires 30d`.
   Осторожно: `add_header` внутри `location` отменяет унаследованные
   `add_header` из блока `server`, security-заголовки придётся продублировать.
   Проверяется только на проде через `curl -I`.
2. **Контраст бренд-цвета.** `--color-green-1: #45a771` с белым текстом даёт
   2.99:1 при норме 4.5:1 — это основная кнопка сайта, используется в 55
   CSS-файлах. Аудит `color-contrast` валится на всех маршрутах, но
   доступность и так держится на 94–95, поэтому менять бренд-цвет без решения
   заказчика не стал. Для 4.5:1 зелёный нужно затемнить примерно до `#358457`.
3. **`heading-order`.** Карточки по всему сайту используют `<h5>` как
   оформительский заголовок, пропуская уровни. Чинится по виджетам,
   на оценку влияет слабо.
4. **RSC-поток.** В документе главной 610 КБ из 1.04 МБ — это сериализованные
   пропсы серверных компонентов. Причина в том, что виджеты клиентские
   и получают контент-константы пропсами через границу сервер/клиент. Если
   константы импортировать внутри самих клиентских виджетов, данные не будут
   сериализоваться дважды. Это заметный рефакторинг, вынесен за рамки задачи.
5. **`/letter`** даёт SEO 66 из-за `is-crawlable` — страница закрыта
   от индексации и исключена из карты сайта. Если это намеренно, маршрут
   стоит исключить из проверки порога.

## Проверка

Тестового фреймворка в проекте нет. Набор проверок:

```bash
cd src
tsc --noEmit
pnpm build
pnpm lint <затронутые файлы>     # репозиторий целиком не форматируем

node scripts/check-metadata.mjs                       # SEO-слой цел
for t in site-url normalize-meta-text build-metadata sitemap og-title; do
  node --import ./scripts/checks/alias-hook.mjs ./scripts/checks/$t.test.mjs
done
```

Плюс визуальная проверка на 375 / 768 / 1441 / 1920 px — особенно первого
экрана (изменилось поведение анимации), модальных окон и куки-панели.
