# Сторисы: ТЗ для бекенда

Виджет сторисов на главной (`src/widgets/stories`) готов и ждёт данные из админки. Решения: одна лента на главной без фильтров; конвертацию медиа делает бекенд.

## 1. Модели

**StoryGroup** (группа = один кружок в ленте)

| поле | тип | обяз. | заметки |
|---|---|---|---|
| `id` | int | да | PK |
| `title` | str, ≤ 30 символов | нет | подпись под кружком и в шапке просмотрщика. Длинные подписи обрезаются вёрсткой, поэтому лимит нужен |
| `preview` | image | да | обложка кружка, квадрат, рекомендуемый размер от 300×300 |
| `order` | int | да | порядок в ленте (по возрастанию), drag-n-drop в админке |
| `is_published` | bool | да | по умолчанию `false` |
| `publish_from` / `publish_to` | datetime, null | нет | окно показа (для акций с датами). Пустое поле = без ограничения |
| `updated_at` | datetime | авто | обновляется **и при изменении любого вложенного кадра** (по нему фронт снова помечает группу непросмотренной, когда в неё добавили кадр) |

**StoryItem** (кадр внутри группы, inline в форме группы)

| поле | тип | обяз. | заметки |
|---|---|---|---|
| `id` | int | да | PK |
| `group` | FK → StoryGroup | да | `on_delete=CASCADE` |
| `type` | enum `image` \| `video` | да | |
| `image` | image | при `type=image` | вертикальный кадр 9:16, исходник от 1080×1920 |
| `video` | file | при `type=video` | mp4/mov/webm, ≤ 60 с, ≤ 100 МБ на загрузку |
| `duration` | int (мс), null | нет | только для `image`: сколько держать кадр. Пусто = фронт берёт 7000. Для видео не нужно, длительность определяет сам ролик |
| `order` | int | да | порядок кадров в группе |

**Валидация при сохранении:** для `image` обязателен `image` и пустой `video`, для `video` наоборот. `duration` в диапазоне 2000–30000.

## 2. Обработка медиа (на бекенде)

- **Картинки** (`preview`, `image`): тот же конвейер, что у блога/акций. На выходе `webp` + `avif` (+ `original`); `mobile` — уменьшенная копия до ~750 px по ширине.
- **Видео**: транскод в **H.264 + AAC, mp4, `faststart`**:
  - `src` — до 1080p по длинной стороне, ~3–4 Мбит/с;
  - `mobile` — до 720p, ~1.5 Мбит/с;
  - `posterSrc` — первый кадр, jpg/webp. Его показываем, пока видео грузится.
- Транскод лучше вынести в фоновую задачу. Пока она не завершена, кадр в API **не отдаётся** (иначе у пользователя будет битое видео).
- URL отдавать **относительными** `/media/...`: `next.config.mjs` уже проксирует `/media/*` на бекенд, так что файлы получаются same-origin.

## 3. Эндпоинт

`GET /api/v1/stories`: публичный, без пагинации, без параметров.

Фильтрация на бекенде:
- `is_published = true`, `now()` попадает в `[publish_from, publish_to]`;
- кадры, у которых не завершена обработка медиа, исключаются;
- **группы без кадров не отдаются**;
- сортировка групп и кадров по `order`.

Ответ **в camelCase** (как в блоге: `previewPoster`, `publishDate`), без полей со значением `null` (`response_model_exclude_none=True`):

```json
{
  "groups": [
    {
      "id": 1,
      "title": "О клинике",
      "updatedAt": "2026-10-20T12:00:00Z",
      "preview": {
        "webp": { "src": "/media/stories/1/preview.webp", "mobile": "/media/stories/1/preview-m.webp" },
        "avif": { "src": "/media/stories/1/preview.avif" }
      },
      "items": [
        {
          "id": 11,
          "type": "image",
          "duration": 4000,
          "poster": {
            "webp": { "src": "/media/stories/1/11.webp", "mobile": "/media/stories/1/11-m.webp" }
          }
        },
        {
          "id": 12,
          "type": "video",
          "source": { "src": "/media/stories/1/12.mp4", "mobile": "/media/stories/1/12-m.mp4" },
          "posterSrc": "/media/stories/1/12-poster.webp"
        }
      ]
    }
  ]
}
```

Схема ответа: `StoryImageItem = { id, type: "image", poster: PictureFormatSchema, duration? }`, `StoryVideoItem = { id, type: "video", source: { src, mobile? }, posterSrc? }`. Это дискриминированное объединение по `type`. Поле `poster` у картинки — тот же `PictureFormatSchema`, что в блоге.

Кэш: фронт ревалидирует раз в 60 с, поэтому изменения из админки появятся на сайте в течение минуты.

## 4. Админка

- Список групп: превью, название, статус, окно показа, количество кадров, сортировка перетаскиванием.
- Форма группы: inline-список кадров с сортировкой, превью загруженного медиа и статусом обработки видео («обрабатывается / готово / ошибка»).
- Подсказки у полей загрузки: «вертикальный кадр 9:16, от 1080×1920», «видео до 60 секунд».
